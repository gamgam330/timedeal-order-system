## 데이터
- 매 실행 전에 `make k6-reset`으로 초기화한다: 주문과 결제 삭제, 상품 1 재고 100개, 상품 2 재고 1,000만 개
- 매 실행 후 `make k6-check`로 정합성을 검사한다: 남은 재고 + 판매 수량 = 초기 재고

## 측정 전 체크리스트
- [ ] 전원 어댑터 연결 (배터리 모드에서는 잠자기와 성능 제한이 걸릴 수 있다)
- [ ] `make k6`로 실행 (내부에서 `caffeinate -dimu`로 잠자기를 막는다)
- [ ] 측정 중에는 빌드나 IDE 인덱싱 같은 무거운 작업을 하지 않는다
- [ ] 실행 후 앱 로그에서 `Thread starvation or clock leap detected`가 있는지 확인한다. 있으면 그 결과는 무효다

## 변경 이력
| 날짜 | 변경 | 영향 |
|---|---|---|
| 2026-10-26 | Redis 컨테이너 추가 (03단계) | 같은 머신의 CPU를 나눠 쓰므로 02단계 수치와 직접 비교하지 않는다. 비교 기준(원자적 UPDATE, 비관적 락)은 Redis를 띄운 상태에서 다시 측정한다 |

## 알려진 한계
- K6, 애플리케이션, Docker가 같은 머신의 CPU를 나눠 쓴다. 부하를 주는 쪽과 받는 쪽이 서로 영향을 준다. 절대 수치보다는 **같은 환경에서 바꾸기 전과 후를 비교하는 용도**로 본다.
- macOS 위의 Docker는 리눅스 VM을 거치므로 네이티브 리눅스보다 I/O가 느리다.
